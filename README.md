# Лабораторна 01 — Коробка байтів

Інтерактивна програма моделює 4096 байтів пам'яті. Кожна клітинка має тип `std::uint8_t`: це рівно один байт, а його беззнакова арифметика визначена по модулю 256. `int` зазвичай займає кілька байтів і його знакове переповнення не визначене, тому він не підходить для клітинки пам'яті.

## Збірка і запуск

Відкрийте `Lab 1.slnx` у Visual Studio та зберіть конфігурацію Debug x64. У терміналі після запуску доступні:

```text
help
sizeof
dump
get <addr>
set <addr> <value>
inc <addr>
quit
```

Адреси: `0..4095`; значення: `0..255`. Числа можна вводити десятково або з префіксом `0x`.

## Контрольні приклади

```text
set 0 65
get 0
65  0x41  0b01000001  'A'
set 0 255
inc 0
get 0
0  0x00  0b00000000  '.'
set 5000 1
Error: address 5000 is out of bounds (0..4095).
```

## Фактичний вивід у Debug x64 (MSVC)

`sizeof`:

```text
sizeof(char)       = 1
sizeof(uint8_t)    = 1
sizeof(uint16_t)   = 2
sizeof(int)        = 4
sizeof(float)      = 4
sizeof(double)     = 8
```

Перші три рядки початкового дампу:

```text
0000  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
0010  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
0020  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
```

## Досліди M4

1. `set 0 255`, `inc 0`, `get 0` дає `0  0x00  0b00000000  '.'`. Беззнаковий байт загортається за модулем 256. На відміну від цього, переповнення знакового `int` у C++ має невизначену поведінку; UBSan повідомляє про неї.
2. Для `0.1 + 0.2 == 0.3` порівняння може дати `false`: значення 0.1 і 0.2 округлюються до найближчих доступних двійкових дробів, а їх сума не збігається точно з представленням 0.3.
3. Після запису `65`, `66`, `0` дамп показує `|AB..............|`. Це байти ASCII `A`, `B` і нуль-термінатор C-рядка.
4. Прибирання `{}` з ініціалізації масиву залишає його елементи неініціалізованими. Тоді читання через `dump` має невизначену поведінку; результат не є стабільним і цей експеримент не запускали.

Після `dump` рядок за адресою `0000` містить 16 байтів і колонку ASCII; недруковані значення показуються крапкою. Наприклад, після `set 0 65`, `set 1 66`, `set 2 0` колонка починається з `|AB..............|`.

## Пояснення для захисту

- Тип задає, скільки пам'яті займає значення та як трактуються його біти.
- `std::uint8_t` задає фіксовану ширину в 8 бітів; його значення — від 0 до 255.
- `inc` читає байт, збільшує його й записує результат назад у байт. Перетворення 256 у `std::uint8_t` дає 0.
- `0.1 + 0.2 == 0.3` може бути хибним, бо ці десяткові дроби не мають точного двійкового представлення.
- ASCII-колонка показує символи лише для байтів `0x20..0x7e`; решта відображаються крапкою.

## Локальні перевірки

Команда `sizeof` друкує розміри типів у поточній збірці. Скопіюйте цей вивід у звіт разом із першими трьома рядками `dump` після запуску та результатами чотирьох дослідів із завдання. Дослід із видаленням `{}` навмисно не запускайте у звичайній збірці: читання неініціалізованих байтів є невизначеною поведінкою.

Компілятор-залежний вивід `sizeof` можна отримати, тимчасово надрукувавши `sizeof(char)`, `sizeof(std::uint8_t)`, `sizeof(std::uint16_t)`, `sizeof(int)`, `sizeof(float)` і `sizeof(double)`.
